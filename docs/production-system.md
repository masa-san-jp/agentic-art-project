# 自律的な制作プラン生成システム

Agentic Artでは、人間が一つの完成案を直接指定するのではなく、エージェント群がテーマ・条件・参照可能な知識から複数の制作プランを考案し、その違いを比較できる形で残します。

このページは、`agentic-art-orchestration` が担う自律的な制作プラン生成の流れを、公開資料として説明するものです。個別の研究台帳、内部ログ、エージェント向け指示、個人由来の原資料はここに収録しません。

## 生成の流れ

```text
テーマ・目的・条件
        │
        ▼
入力信号と参照可能な知識
        │
        ▼
候補空間の生成・安全／権利のゲート
        │
        ▼
複数の制作仮説の比較・選択
        │
        ▼
研究から制作への handoff
        │
        ▼
人間が読める制作プラン
        │
        ▼
公開用の計画レコード
```

オーケストレーション・リポジトリは、モデルを呼び出す展示作品そのものではありません。Claude CodeやCodexのようなコーディングエージェントが、リポジトリに定義された台帳・スキーマ・検証ツール・停止条件を使って、複数リポジトリにまたがる制作経路を実行できるようにします。

## 一つの入力から複数のプランへ

一つの入力に対して一つの答えを返すのではなく、異なる参照、判断、反対案、未解決事項を持つ候補を分けます。個々のプランには、少なくとも次の要素を残します。

- どのような鑑賞体験を目指すか
- 何をテーマとし、どの前提に対抗するか
- 作品の中心機構と、機構が成立しない条件
- 必須要件、受入試験、工程、未解決事項
- 外部制作・購入・契約・展示へ進む前に必要な確認

候補を増やすことは、すべてを制作することを意味しません。比較可能な数のプランを用意し、人間が制作上の選択を行える余地を残すことが目的です。

## 100件規模を扱う設計

100件以上のプランを扱うため、プロジェクト単位のディレクトリ、安定した識別子、依存関係付きのタスク、再開可能な実行記録を使います。各プロジェクトを独立した作業単位として扱い、次の性質を保ちます。

- 同じ入力と同じ条件からは、同じ候補順序と記録形式を再現できる。
- 一部の失敗や停止が、別プロジェクトの記録を上書きしない。
- 未解決事項や不確実性を、完了した事実として埋めない。
- 検証前の物理制作や外部効果を、プラン生成の成功と混同しない。

100件規模を目標にした設計資料と、実際に生成された個別プランは別のものです。このリポジトリでは、個別プランを `plans/Pxxxx-slug/` に一件ずつ収録します。

## 自律性と人間の境界

エージェントは、候補の生成、調査の整理、仮説の比較、制作プランの文書化を自律的に進めます。一方、次の行為はプラン生成の成功だけでは許可されません。

- 物理制作、購入、支払い、契約、会場設営
- 個人の参加を伴う試験や外部サービスへの送信
- 作品・計画・素材の外部公開を確定する操作
- Gitのcommit、push、PR、merge、release、visibility変更

公開用の計画レコードは、生成されたプランを人間が読める形にしたものです。レコードが`published`であっても、そこに書かれた制作を実行済み、受入試験を通過済み、展示許可済みとは解釈しません。

## 公開projectionの考え方

`agentic-art-project`へ取り込むのは、オーケストレーション出力のうち、公開用に整理した正本だけです。内部の`research-project/`、`handoff/`、実行ログ、会話、エージェント向けcontext、credential、ローカルパスはそのままコピーしません。

公開レコードは次の単位で整理します。

```text
plans/P0001-example/
├── README.md       # 展示カタログから読む紹介
├── plan.md         # 公開用の制作プラン本文
└── metadata.yaml   # 識別子、状態、可視性、権利状態、出典
```

画像や動画などのメディアは、公開許諾と権利状態が確認された場合だけ、対応する作品レコードの`media/`へ収録します。計画本文の説明用素材を、内部出力から自動的に持ち込むことはしません。

## READMEとカタログの同期

制作プランの正本一覧は `plans/index.yaml` です。`plans/README.md` とルート `README.md` の制作プラン一覧は、インデックスを読みやすいリンクへ展開した生成ブロックであり、個別に編集しません。ローカルでレコードを追加・修正した場合は次を実行します。

```bash
python3 tools/catalog_sync.py --write
python3 tools/catalog_sync.py --check
```

オーケストレーションの自動plan投影が `public_projection_root` に新しいプランを反映するとき、ルートREADMEに `<!-- agentic-art:catalog:start -->` と `<!-- agentic-art:catalog:end -->` がある場合は、ルートからのリンク一覧も同じtransactionに含めます。ルートREADMEの概念説明、リポジトリ関係表、代表作品の紹介は自動置換の対象外です。関連リポジトリのURLと役割は [`repositories.yaml`](repositories.yaml) で管理します。

## このカタログの読み方

各プランは、完成作品の説明ではなく、エージェントがどのような制作仮説を採択し、何を検証前の問題として残したかを読むための記録です。プラン同士を比較することで、同じ入力からどのような体験、媒体、距離、参加条件が分岐したかを確認できます。
